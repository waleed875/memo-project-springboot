# خطة نقل الخادم من .NET 8 إلى Spring Boot

## المبادئ

- **إعادة تنفيذ السلوك، لا مجرد ترجمة C# إلى Java**: القاعدة الوظيفية والإجراءات والصلاحيات والتقارير يجب أن تعطي نفس النتائج على نفس البيانات.
- الاحتفاظ بواجهة React الموجودة في المرحلة الأولى؛ واجهات HTTP ومساراتها والاستجابات ورموز الحالة وملفات التنزيل مهمة للتوافق.
- يبقى PostgreSQL ومخططه مرجعًا ثابتًا مبدئيًا؛ لا نستبدله بـ JPA-generated schema.
- الترحيل يتم عبر وحدات رأسية (Vertical Slices) لها اختبارات end-to-end، لا استبدال دفعة واحدة.

## المراحل

### 0. جرد المرجع (لا تعديل للمستودع الأصلي)
- حصر APIs الموجودة، نماذج الإدخال/الإخراج، مصادقة الجلسات، CSRF، الصلاحيات.
- حصر قواعد الأعمال في Core/Data وخدمات التقارير والمذكرات والمرفقات.
- توثيق 70 ترحيل SQL، والمخطط الفعلي من نسخة اختبار لقاعدة البيانات.
- التقاط نتائج اختبارات سلوك مرجعية Golden Master للحالات الصحيحة والخاطئة.

### 1. التأسيس
- اختيار Java 21 LTS وإصدار Spring Boot مدعوم بعد تدقيق توافق المكتبات.
- إعداد Gradle أو Maven، Spring Web, Spring Security, Validation, Actuator, JDBC/jOOQ بحسب تعقيد الاستعلامات.
- اتصال PostgreSQL بقاعدة اختبار فقط، مراقبة، structured logging، correlation id.
- اختبارات JUnit 5 + Testcontainers + OpenAPI.

### 2. الهوية والأمان
- نقل جلسات الدخول، BCrypt، تغيير كلمة المرور الإلزامي، انتهاء الجلسة، CSRF.
- تطبيق فحص الصلاحيات مركزيًا في Service/Controller وعدم تكرار ثغرات وصول المرفقات أو الإعداد أو التحديثات.
- التحقق من توافق التجزئات الحالية وإدارة Cookie SameSite/Secure وTrusted Proxy.

### 3. نطاق المذكرات
- إنشاء/تعديل/حذف المذكرات، التسلسل، الحالات، المراجعات وسير الموافقات.
- المرفقات: ملكية السجل، صلاحية القراءة/الكتابة، نوع الملف، الحجم، التخزين الدائم.
- حماية التزامن والمعاملات وقيود القاعدة.

### 4. التقارير والوظائف المتبقية
- استعلامات Dashboards والتجميع والفلاتر وترقيم الصفحات.
- تصدير PDF (Chromium/بديله بعد اختبار RTL والخطوط)، XLSX، وHTML.
- التحديثات وRSA signatures وmanifest compatibility إن بقيت خدمة التحديث ضمن النطاق.

### 5. التشغيل والنشر
- بناء Docker متعدد المراحل non-root، فحص Health وReadiness، Compose مع volumes وشبكة داخلية.
- CI/CD (المزود يحدد لاحقًا؛ Gitea مؤجل): tests → build → image scan → push immutable image → release approval.
- Portainer: نشر Stack من Git مع tagged image / digest، مراقبة وتنفيذ rollback متوافق مع القاعدة.
- قطع الإنتاج بعد اختبار النسخ الاحتياطي والاستعادة ومقارنة التقارير والعمليات الحرجة.

## معايير إنهاء كل شريحة

1. اختبار API مطابق لاستجابة المرجع حيث يلزم.
2. اختبار قاعدة البيانات والمعاملات والأخطاء والحدود.
3. اختبارات التفويض بما فيها مستخدم مختلف المالك.
4. توثيق قرار تغيير السلوك إن كان إصلاحًا أمنيًا مطلوبًا.
5. لا تعديل على المستودع الأصلي.
