# إلحاق مرفق أصلي وروابط مقابلة بنواة إنشاء المذكرة

**الحالة:** شريحة تطوير محدودة في `feature/notes-create-attachments-links` فوق طلب الدمج #11، وليست واجهة `POST /api/notes` الكاملة. لا تعديل على المصدر الأصلي.

## المراجع المقروءة

- `waleed875/memo_project@dd8eb2ba57864eac2371a3addd0b786ccefa2367`
- `AttachmentFilePolicy.cs`: أنواع `pdf/png/jpg/jpeg/bmp/gif/tif/tiff`، التوقيع والحد 10 MiB.
- `013_add_duplicate_and_note_links.sql`, `026_enforce_single_entry_exit_link.sql`, `034_enforce_cross_side_single_note_link.sql`، و`063_add_note_source_contract.sql`: صلاحية الربط، النوع المقابل والشركة، روابط التوافق.
- `068_add_note_attachments_table.sql`: تخزين المرفقات المتعددة وإتاحة الرجوع للمرفق الأساسي.

## ما أُضيف

- `NoteAttachment`: نسخة دفاعية من بايتات المرفق عند البناء والقراءة؛ لا تغيير بعد التقاط البصمة.
- `NoteAttachmentPolicy`: نوع ملف مسموح مع التوقيع الصحيح، منع الملف الفارغ وما يتجاوز 10 MiB، منع الاسم الذي يحتوي مسارًا أو محارف تحكم. يشمل PDF وجود `%%EOF` في آخر 1024 بايت.
- `NoteCreateCommand`: إضافة مرفق أصلي اختياري واحد و`relatedNoteIds` إلى النموذج الداخلي، مع الاحتفاظ بالمنشئ السابق للاختبارات.
- `JdbcNoteCreator`: إضافة اسم ونوع وبايتات المرفق إلى `core.notes`، وصف مقابل في `core.note_attachments` (068)، وروابط في `core.note_links` (013) وسجل `LINK_NOTES` في `audit.logs`؛ داخل **معاملة إنشاء واحدة** مع حجز العملية والمؤشرات والحالة وتدقيق الإنشاء.
- التحقق من روابط غير صفرية وغير ذاتية وغير مكررة ومن نفس الشركة، ويجب أن يكون الربط بين `ENTRY` و`EXIT` في الاتجاهين. تُطبّق طبقة PostgreSQL الأصلية triggers لضمان التزامن إذا تم استيراد الترحيلات الفعلية.
- ترقية وسم بصمة العملية إلى `note-create-core-2` وإدراج اسم المرفق وحجمه وSHA-256 لمحتواه وجميع معرّفات الروابط مرتبة ضمن البيانات الموقّعة. إعادة محاولة ببايت مختلف أو روابط مختلفة **تُرفض**.
- الوحدة: اختبارات نوع الملف والتوقيع والاسم والنسخ الدفاعي. PostgreSQL: حفظ المرفق والربط واستجابتهما لإعادة المحاولة، رفض مرفق/رابط غير صحيح، تراجع المرفق والربط عند فشل التدقيق.

## محاذير التوافق والإطلاق

1. `NoteCreateCommand` الحالي ليس `SaveNoteRequest` الأصلي: لا يوجد HTTP `POST/PUT`، ولا تدعم هذه الشريحة `isLoot/isInvoice` أو تصنيفات التكرار أو حمولة المصادر المركبة أو المرفقات المتعددة المرسلة دفعة واحدة.
2. المخطط الاختباري يبني أعمدة محدودة من 013/068؛ لا يثبت صحّة جميع triggers، خاصة مزامنة مصادر `EXIT` من ترحيلات 063 و070. يلزم replay كامل 001–070.
3. بصمة Java الداخلية لا تطابق بصمة C# v2، لذلك لا تدعم إعادة التشغيل العابرة بين اللغتين تلقائيًا.
4. فحص Magic bytes حدّ أولي، لا يغني عن فحص برمجيات خبيثة أو التحقق العميق من PDF/الصور أو ضوابط التحميل على HTTP.
5. لم يفتح أي مسار جديد لكتابة المذكرات، ولم يُنشر شيء على الإنتاج، ويجب بقاء `main` دون تعديل إلى حين مراجعة سلسلة PRs واختبارات Golden Master.

يجب اعتماد تشغيل Maven `verify` الأخضر، ثم مراجعة طبقة قاعدة البيانات الأصلية قبل تطوير API الإنشاء العام.
