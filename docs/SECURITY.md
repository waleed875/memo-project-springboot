# قواعد أمان لازمة قبل الإنتاج

- لا تنسخ سلوك أخطاء التفويض الموجودة في الكود القديم؛ انقل قواعد الأعمال مع إصلاح الثغرات المثبتة.
- صلاحيات ADMIN صريحة على إعدادات الاتصال وترحيلات القاعدة ونشر التحديثات.
- مصادقة وتفويض لكل endpoint للتعامل مع المرفقات، مع تحقق من ملكية المذكرة وصلاحية التعديل.
- CSRF محكم للطلبات المؤثرة على الحالة إن استُخدمت Cookies للجلسات.
- Session cookies: HttpOnly, Secure, SameSite وفق بيئة HTTPS.
- تحقق من المضيف وTrusted proxy وCORS؛ لا تستخدم wildcards لمضيفي الإنتاج.
- الأسرار تأتي من إدارة Secrets/Files منفصلة خارج Git، وتُدوّر وفق إجراء موثق.
- صورة Java محدّثة LTS، CVE scan للصور والمكتبات، non-root، والحد الأدنى من الصلاحيات.
- تحكم في الوصول إلى Portainer وContainer Registry (Gitea عند تفعيله) وWebhook كأسرار تشغيل حساسة.
- نسخ احتياطي مشفر ومجرّب والاستعادة في بيئة اختبار.
- المقارنة بين سلوك القديم والجديد لا تعني الحفاظ على الثغرات؛ توثق الاستثناءات الأمنية وتغطى بالاختبارات.
