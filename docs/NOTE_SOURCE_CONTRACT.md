## العقد الوظيفي من C#

- `GET /api/notes/{id}/source`: قراءة وصف المصدر، وتفاصيل مراجع الخروج، وملخص الفواتير، ولا يعيد بايتات مرفقات الفاتورة.
- `POST /api/notes/{id}/source`: إنشاء مصدر أو استبدال نوعه وحمولته على مذكرة إدخال قائمة.
- `DELETE /api/notes/{id}/source`: إزالة المصدر وكافة حمولة النوع المختار، مع إزالة صفة الغنائم.
- القيم `Exit` و`Invoice` و`Loot` و`Other` في JSON تطابق Enum C#، وتخزن في PostgreSQL كـ `EXIT`, `INVOICE`, `LOOT`, `OTHER`.
- `Exit`: واحدة أو أكثر من مذكرات الخروج، ويمكن أن تكون متعددة ومترتبة. `Invoice`: فاتورة واحدة أو أكثر مع بياناتها ومرفق اختياري؛ `Loot`: وصف إلزامي؛ `Other`: وصف إلزامي.
- قاعدة البيانات في migration 063 هي المرجع النهائي لجداول `note_sources`, `note_source_exit_refs`, `note_source_invoices`, `note_source_loot`. ويتغير السلوك عند تشغيل triggers تحديث الروابط من 070، لذا يلزم اختباره قبل الإنتاج.

## طبقات التنفيذ

- `notes/domain`: `NoteSourceType`, `NoteSourceDraft`, `NoteSourceView`, `NoteSourcePolicy`، وقواعد `NoteAttachmentPolicy`.
- `notes/application`: `NoteSourceService` للتحقق من جلسة المستخدم ودوره وملكيتة وبوابة الكتابة، و`NoteSourceStore` منفذ لا يعتمد على Spring.
- `notes/infrastructure`: `JdbcNoteSourceStore`. تحقق مجدد من ملكية المذكرة في SQL **داخل معاملة الكتابة بعد قفل الصف**، ومن أنها من نوع `ENTRY`، ومن صلاحية كل مرجع إخراج وحصره بالشركة نفسها. قراءة المصدر تستخدم لقطة واحدة في `REPEATABLE_READ`.
- `notes/api`: `NoteSourceController` محول عقد HTTP فقط. تبقى واجهة تنزيل مرفق فاتورة المصدر مغلقة لحين نقل قواعد الوصول والأحجام/النوع.
- `platform/security`: فتح المسارات الثلاثة المحددة فقط، وعدم إزالة CSRF عن POST/DELETE.

## سلامة المعاملة والتدقيق

1. `SELECT ... FOR UPDATE` على صف المذكرة: يمنع تداخل عمليتي تحديث المصدر.
2. بناء `old_value` بصيغة JSONB منظمة، تشمل النوع والحقول الأساسية والمراجع والفواتير و**حجم المرفق لا محتواه**.
3. `INSERT ... ON CONFLICT(note_id) DO UPDATE` للحفاظ على معرّف المصدر، ثم حذف حمولات النوع السابق وإدخال حمولة النوع الجديد.
4. ضبط `core.notes.is_loot` وفق المصدر.
5. بناء `new_value` وتسجيل `UPDATE_NOTE_SOURCE` ضمن نفس المعاملة. وعند الحذف `REMOVE_NOTE_SOURCE` مع `new_value=null`.
6. عند فشل SQL أو التدقيق يتراجع المصدر القديم وحمولته و`is_loot` بلا فقد.

الاختبارات: JUnit لسياسة الأنواع الأربعة وتحقق الصلاحية، وMockMvc لجلسات المستخدم وCSRF والمدخلات، وTestcontainers PostgreSQL 16 لانتقالات `Exit → Loot → Invoice → Other`، وللمراجع المتعددة، وحفظ بيانات الفاتورة ومرفقها، وللمالك وللتراجع عند فشل التدقيق.
